# SSH 與 SFTP 整合：實作計畫（fork 專屬）

> 狀態：設計已確認（2026-11-04），Phase 1、2 完成並提交到功能分支，下一步 Phase 3。進度見 §10
> 分支：`feat/ssh-sftp-unified`，每個 Phase 完成後合回 `omar/custom`
> 對象：接手實作的人或新對話。本文件可獨立閱讀，不需要先前的對話紀錄。
> 前身：[`ssh-sftp-pages-plan.md`](./ssh-sftp-pages-plan.md)。本文件只推翻它的 D1（兩個獨立頁面），D2 到 D7 都保留。

## 1. 目標

把側欄的 SSH、SFTP 兩個頁面併成一個。**每個分頁就是一台主機的工作區**，裡面有一個終端機和一個檔案工作台，可以只看終端機、只看檔案，或上下並排，兩邊都是用到才連線。

另外新增兩個功能：

1. **常用指令**：可以編輯名稱、指令模板、模板參數。
2. **多開與同步輸入**：一次開多台主機、並列顯示、隨時增減連線，並可同步輸入。

連線方式不重做：終端機仍是本機 PTY 裡的系統 `ssh`，檔案仍走獨立的 ssh2 連線，不經過 relay，遠端不需要 Node。每個動作先列出確切指令再執行的流程也完整保留。

## 4. 核心模型

### 4.1 資料

```ts
// components/ssh-page/remote-session-store.ts（zustand + localStorage: orca.remoteSessions）
type RemoteLayout = 'terminal' | 'split' | 'files'

type RemoteSession = {
  tabId: string // global-ssh-sessions 裡的終端機分頁 id
  targetId: string // 取代 label 反查
  layout: RemoteLayout
  dockHeight: number // 並排時檔案區的高度
  terminalStarted: boolean // false：ssh 指令還沒確認，不掛 TerminalPane，也不會有 PTY
}
```

### 4.2 規則

- **分頁列用上游的 `TabBar`**：拖曳、改名、顏色、關閉其他都已經有，`SftpTabStrip` 刪除。資料夾名稱在 `use-ssh-session-items.ts` 組標題時接上，不寫回 store，也不用改上游。
- **版面切換器放在分頁列右端**，不多佔一列高度。
- **用到才連線**：終端機要按「連線」並確認指令才啟動；檔案工作台第一次顯示時才連線（沿用 `SftpTabPanels` 的 `shownTabIds`）。
- **切版面只用 CSS 隱藏**，PTY、資料夾、選取、清單都留著。
- **同一台主機想看兩個資料夾，就開第二個分頁**，共用同一條 SFTP 連線。
- **並排的分隔線放開才套用高度**，拖曳時只顯示一條指示線，避免每一格都送 SIGWINCH 給遠端。

### 4.3 兩個半邊的狀態

| 半邊   | 狀態                 | 怎麼知道                                          | 畫面                                       |
| ------ | -------------------- | ------------------------------------------------- | ------------------------------------------ |
| 終端機 | 未啟動               | `terminalStarted = false`                         | 佔位文字加「連線」，按下才跳指令確認       |
|        | 使用中               | `pty.getForegroundProcess` 回傳 `ssh`             | 正常顯示                                   |
|        | 已結束               | 看過 `ssh`，現在前景是 shell                      | 橫幅寫明「現在是本機 shell」，提供重新連線 |
|        | 未知                 | 查不到前景程序（null）                            | 不顯示橫幅，不下結論                       |
| 檔案   | 未連線               | 工作台還沒掛載                                    | 切到檔案版面才開始連                       |
|        | 連線中／已連線／失敗 | `SshConnection.onStateChange` 經新的 `sftp:state` | 窗格標題旁的狀態字，加「中斷連線」         |
|        | 閒置斷線             | 沿用 5 分鐘                                       | 下次操作自動重連，帶回已驗證的憑證         |

終端機的「使用中」判斷是常用指令和同步輸入的安全基礎：只有確定前景是 `ssh` 才會送文字，否則指令會跑在使用者自己的電腦上。

## 5. 操作規則

### 5.1 開分頁與切換

| 操作                                            | 行為                                                                    |
| ----------------------------------------------- | ----------------------------------------------------------------------- |
| 點主機                                          | 有分頁就跳過去，沒有才開新分頁（終端機版面，先確認指令）                |
| ⌘／Ctrl 點主機                                  | 加入多選，下方出現「開啟並列」；已經在並列時變成「加入並列」（Phase 4） |
| 主機列尾圖示、右鍵選單                          | 開新終端機分頁，或開新檔案分頁（不跑 ssh）                              |
| ⌘T／⌘W                                          | 開主機選擇器／關分頁。關分頁時進行中的傳輸繼續跑                        |
| ⌘⌥1／2／3（Windows、Linux 是 Ctrl+Alt+1／2／3） | 切換終端機／並排／檔案。只在這個頁面攔截                                |
| 舊的 SFTP 分頁                                  | 第一次進頁面時把 `orca.sftpTabs` 轉成檔案版面的分頁，之後不再讀         |

### 5.2 終端機和檔案的連動（Phase 6）

| 動作           | 行為                                                 | 防呆                                                                                                                                                                                   |
| -------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| cd 到這裡      | 把 `cd -- '/var/www/app'` 貼進終端機，**不按 Enter** | 全螢幕程式（xterm alternate screen）時停用；只在 ssh 使用中可用；Windows 主機改成複製路徑                                                                                              |
| 跟隨終端機     | 遠端 shell 回報資料夾（OSC 7）時，檔案窗格跟著切     | 預設關閉；沒收過回報就停用，並提供可複製的 `~/.bashrc` 設定，**不自動改伺服器**；hostname 等於本機時忽略（那是 ssh 結束後的本機 shell），和第一次回報不同時也忽略（那是又 ssh 到別台） |
| 拖檔案到終端機 | 貼上引號包好的遠端路徑，不按 Enter                   | 同 cd 到這裡                                                                                                                                                                           |

## 6. 常用指令（Phase 3）

左欄多一個「指令」分頁。點一下填參數、看到最後的完整指令，再決定貼上或執行。

### 6.1 為什麼不加在 Quick Commands 上

- **加了欄位存不起來**：`normalizeTerminalQuickCommands` 逐欄重建物件，`parseNormalizedTerminalQuickCommands` 要求欄位完全相符（`terminal-quick-commands.ts:122-146,196-218`）。手機和 RPC 都走這條路，要改就得一起改上游、手機和 goldens。
- **模板會外流**：Quick Commands 也會從專案終端機和手機執行，那裡沒有填參數的畫面，`{{service}}` 會原封不動送進 shell。
- **範圍對不上**：它的範圍是全域或 repo，這裡需要全部主機、分組或指定主機。

所以用 fork 自己的 store：`userData/ssh-commands.json`，寫法照 `SshVpnStore`。可重用的照用：`flattenTerminalQuickCommand`、`CommandList`。

### 6.2 資料

```ts
// shared/ssh-command-types.ts，用 zod 驗證後才寫檔
type SshCommandParam = {
  key: string // 模板裡的 {{key}}，只允許英數、底線、連字號
  label: string
  kind: 'text' | 'number' | 'select'
  options?: string[] // kind = 'select'
  defaultValue: string
  required: boolean
  quote: 'shell' | 'raw' // shell：自動加引號（預設）；raw：原樣帶入，畫面會標示
}

type SshCommand = {
  id: string
  name: string
  template: string // journalctl -u {{service}} -n {{lines}} --no-pager
  params: SshCommandParam[]
  runMode: 'run' | 'insert' // 新指令預設 insert
  scope:
    | { type: 'all' }
    | { type: 'group'; groupId: string }
    | { type: 'hosts'; targetIds: string[] }
}
```

### 6.3 編輯

- 打字時參數表自動同步：多一個 `{{x}}` 就多一列，拿掉就標示未使用，刪除前不丟已填的設定。
- 內建參數：`{{host}}`、`{{user}}` 是目標主機；`{{path}}` 是檔案窗格目前的遠端資料夾；`{{selected}}` 是選取的項目。
- 模板為空、參數名稱不合法、用了沒定義的參數都不能存。`{{x}}` 寫在引號裡時提醒，因為自動引號會變成兩層。

### 6.4 執行

1. 沒有參數又是「只貼上」的指令直接貼上；其他都開對話框。
2. 填參數並選目標（目前分頁或並列中的主機），下方即時顯示**每台展開後的完整指令**。這個畫面同時就是確認畫面。對話框用 `DialogContent surface="security"`（STYLEGUIDE 要求；現有的 `CommandConfirmProvider` 沒有用，順手補上）。
3. 按「貼上不執行」或「執行」。上次填的值依指令和參數記住。

### 6.5 參數展開規則（純函式 `expandSshCommandTemplate`，每個分支都有單元測試）

| 情況                 | 處理                                                                   | 為什麼                                                              |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 一般的值             | 安全字元原樣保留；其他用 POSIX 單引號，`'` 轉成 `'\''`                 | `nginx; rm -rf /` 只會是一個字串                                    |
| 值裡有換行或控制字元 | 拒絕                                                                   | 換行等於按 Enter                                                    |
| 值以 `-` 開頭        | 提醒，可以繼續                                                         | 引號擋不住選項注入，模板加 `--` 才是根本解法                        |
| 引號方式選原樣帶入   | 不加引號，預覽標示                                                     | 有時候就是要帶多個選項                                              |
| 目標不在 ssh 使用中  | 單一目標拒絕；多台時這台列為略過，其餘照送                             | 否則會跑在本機 shell 上                                             |
| 目標正在全螢幕程式   | 拒絕                                                                   | 字元進 vim 會被當成編輯指令                                         |
| Windows 主機         | 不做自動引號，要求原樣帶入或選單                                       | PowerShell、cmd 的引號規則不同（`SshTarget.remotePlatform` 可判斷） |
| 多台主機             | `{{host}}`、`{{user}}` 每台分開展開；`{{path}}`、`{{selected}}` 不能用 | 那兩個只屬於單一分頁的檔案窗格                                      |

刻意不做：密碼類型的參數（會進 shell history 和畫面）、匯出匯入、和手機同步。

## 7. 多開與同步輸入（Phase 4、5）

### 7.1 多開與並列

- ⌘／Ctrl 點主機多選，或對分組按右鍵「全部連線」。同一個對話框列出每一台需要新開的 `ssh` 指令，已連線的主機直接沿用，不會多開一條。
- 每個終端機自己跑 ssh，登入提示在各自的窗格裡。
- 最多 9 個，2 個並排、4 個 2×2、9 個 3×3。
- **並列只改變終端機區顯示什麼**：目前的分頁在並列裡才顯示格子，不在就單獨顯示。1 個分頁仍是 1 台主機；並排時下方顯示目前窗格那台主機的檔案。
- 實作上把現有的 `TerminalPane` 從疊在一起改成排成格子，不重新掛載（工作區的分割已經會同時顯示多個 `TerminalPane`，見 `TerminalOverlaySlot.tsx:65`）。

### 7.2 增減連線

| 操作                       | 行為                                                                        | 要確認嗎              |
| -------------------------- | --------------------------------------------------------------------------- | --------------------- |
| 加入已連線的分頁           | 按「加入連線」，從清單選                                                    | 不用，沒有新連線      |
| 加入新主機或還沒連線的分頁 | 同一個清單（沿用 `SshHostPickerDialog`），或 ⌘／Ctrl 點主機後按「加入並列」 | 要，先列出 `ssh` 指令 |
| 從並列移除                 | 窗格標題的 ×。只是不顯示，分頁和 ssh 都還在                                 | 不用                  |
| 關閉連線                   | 分頁的 × 或 ⌘W                                                              | 和現在一樣            |
| ssh 已結束的窗格           | 窗格標題的「重新連線」，接回原位                                            | 要，先列出 `ssh` 指令 |

- 點並列外的分頁或主機會單獨顯示，上方提示列有「加入並列」和「回到並列」，三種版面都看得到；按右上的「並列」或點格子裡任一主機的分頁也會回去。
- 減到只剩 1 個就離開並列。

### 7.3 同步輸入

|          | 逐鍵同步（預設）                         | 整行送出                              |
| -------- | ---------------------------------------- | ------------------------------------- |
| 怎麼用   | 在任一窗格打字，每個按鍵同時送到其他窗格 | 在下方輸入列打完整一行，按 Enter 才送 |
| 適合     | 互動操作：`top`、`Ctrl+C`、一起編輯      | 正式機上一次性的指令                  |
| 主要風險 | `↑` 歷史和 `Tab` 補全每台結果可能不同    | 沒有補全，不能操作互動程式            |

每個按鍵對每個目標判斷一次（純函式 `decideSyncTarget`，每個分支都有單元測試），不送時窗格標題寫原因：

| 條件                   | 結果                           | 為什麼                                     |
| ---------------------- | ------------------------------ | ------------------------------------------ |
| 前景不是 ssh，或查不到 | **不送**                       | 否則指令會跑在使用者的電腦上。最重要的一條 |
| 還沒確認加入同步       | 不送                           | 新主機不會在使用者沒同意的情況下收到輸入   |
| 不在畫面上             | 不送                           | 看不到就不送；從並列移除的窗格也不再收到   |
| 使用者排除了這個窗格   | 不送                           | 每個窗格標題都有「排除」                   |
| 全螢幕狀態和來源不同   | 不送，標示已暫停               | shell 的字元進 vim 會被當成指令            |
| 游標那行像密碼提示     | 不送；來源本身是提示時整批不送 | **盡力而為**，靠比對文字，不保證攔得到     |
| 分頁做過分割           | 不參與                         | 不確定該送到哪個 pane                      |

鏡像範圍：

- **會**：鍵盤輸入，包含輸入法送出的中文和 `Ctrl+C`。
- **不會**：終端機自動回覆、滑鼠回報、焦點回報（重用 `isTerminalQueryReply`、`isXtermMouseReport`、`isPassiveTerminalInputReport`），視窗大小也不同步。
- **含換行的貼上不鏡像**：只送到目前窗格，並提示改用常用指令或整行送出。
- **判斷不了來源就不送**：`subscribeToTerminalInputData` 靠 xterm 內部 API 分辨真人輸入，不可用時一律不鏡像。

開關規則：

- 開啟要確認，對話框列出目標主機。故意不給開啟的快捷鍵。
- 紅色橫條寫明輸入送到哪幾台，來源和接收的窗格都有外框。
- 只有確認過的主機會收到。新加入的窗格顯示「未加入同步」和「加入同步」，按下再確認一次；開同步時 ssh 已結束的主機也一樣。確認過的主機斷線再連回來會恢復。
- 移除窗格後同步繼續，名單變少；移除的是打字中的窗格時焦點移到下一個；能收到的主機少於 2 台就關閉同步。
- 切到並列外的終端機時同步暫停：打字只送給它自己，常用指令也只能送給它，上方寫明「同步輸入暫停中」。回到並列後恢復，不用重新確認，因為名單沒有變。
- 離開頁面、關掉並列時關閉。不保存，重開 Orca 一定是關的。

## 8. 不變的規則

- **先列指令再執行**：開 ssh、重新連線、上傳、下載、移動、刪除維持 `sftp:plan → 確認 → sftp:execute` 和 `CommandConfirmProvider`，renderer 只顯示計畫，main 執行自己存的那份。
- **Orca 不會自己按 Enter**：cd 到這裡、拖路徑、「貼上不執行」只貼文字；會按 Enter 的只有使用者確認過的重新連線和常用指令「執行」。
- **指令不會誤跑在本機**：常用指令和同步輸入都要確定前景是 `ssh`。
- **不動伺服器**：不裝 agent、不改 `.bashrc`、不改遠端登入指令。
- **上傳下載的防護照舊**：`main/sftp/` 只加狀態事件和憑證重用。
- **畫面文字不說沒確認過的事**：查不到前景程序就顯示未知；密碼提示的判斷不說成「已保護」。

## 10. 進度

- 2026-11-04：設計確認，Phase 1 開始。
- 2026-11-04：Phase 1 完成，使用者實測通過。側欄只剩「SSH」；`remote-session-store`（每個分頁的主機、版面、高度、終端機是否已啟動）、`RemoteSessionPanels`（終端機區和檔案區）、`RemoteLayoutToggle`、主機列尾圖示和右鍵選單；舊的 `orca.sftpTabs` 第一次進頁面時轉成檔案分頁。上游只拿掉 `sftp`，沒有新增掛載點。

Phase 1 中發現的事：

- `TabBar` 用 `resolveTerminalTabTitle` 決定標題，`quickCommandLabel` 優先於 `title`，所以資料夾名稱兩個欄位都要帶（`ssh-session-tab-labels.ts`，只影響顯示）。
- 手動新增的主機，`configHost` 只是位址（上游的 `isOpenSshConfigBackedTarget` 有註明），舊的 `buildSshSessionCommand` 卻直接拿來用，會少掉 port 和使用者。已修正。
- Windows、Linux 上 AltGr 回報成 Ctrl+Alt，版面快捷鍵要排除 `AltGraph`，否則會吃掉 AltGr 打出來的字元。

審查後刻意維持的做法：

- **分頁標題是「主機 · 資料夾」，空間不夠時從尾端截斷**，資料夾可能先被截掉。舊的 `SftpTabStrip` 是主機先截斷。沒有改成資料夾在前，因為分不清主機比分不清資料夾危險。
- **`usesConfigAlias` 和 main 的 `isOpenSshConfigBackedTarget` 是兩份相同的規則**。要共用就得把上游的函式搬到 `shared/`，增加 rebase 衝突（前身計畫的 D7），所以留一份並註明來源。
- **沒有 record 的分頁視為終端機已啟動**，因為升級前的分頁都是這樣。如果 localStorage 損毀，原本只開檔案的分頁重開後會變成本機 shell。Phase 2 的「現在是本機 shell」橫幅會涵蓋這個情況。

已知限制：手動主機如果設了 identity file，輸入的 `ssh` 指令不會帶 `-i`（路徑要跨 shell 加引號，舊版也沒有），會改用預設金鑰或問密碼；檔案走 ssh2，不受影響。

- 2026-11-04：Phase 2 完成，使用者實測通過。ssh 結束橫幅和同分頁重新連線（`ssh-session-liveness`、`SshSessionEndedBanner`、`reconnectSessionTerminal`）；`sftp:connectionStates` 和 `onConnectionState` 的狀態事件、檔案區的狀態標示和中斷／重新連線（`SftpConnectionControls`）；頁面底部的傳輸匣（`RemoteTransfersTray`，取代 `SftpTransfersPanel`）；閒置斷線後重連沿用登入資料，使用者自己中斷就清掉。上游只多一個 `export`（`signInEndpoint`）。

前景程序實測（macOS、真實 sshd、daemon PTY）：

| 狀況                             | `getForegroundProcess` | `shellOwnsEveryTtyProcessGroup` |
| -------------------------------- | ---------------------- | ------------------------------- |
| ssh 問密碼、已登入、遠端跑 `top` | `ssh`                  | false                           |
| 經 ProxyCommand                  | `ssh`                  | false                           |
| ssh 結束後                       | 約 100ms 內變回 `zsh`  | true                            |
| 本機跑 `sleep`                   | `sleep`                | false                           |

上面 `shellOwnsEveryTtyProcessGroup` 這一欄是在 E2E 的分頁量的，那裡的 shell 是 PTY 的根程序，沒有 `login`。真實分頁的結果見下一段。

使用者實測發現的問題：真實的 macOS 分頁是 `login → zsh`，閒置時這個值卻一律是 `false`，所以重新連線都被拒絕。原因是 `login` 以 root 執行，in-process 的 libproc 讀不到它的參數，只回報 `(login)`，而 `libproc-argv-completion.ts` 刻意不為 pane 的根程序復原參數，`findPaneShell` 又要求名稱是 `login`。libproc 讀取器（10-29）讓 10-16 的 `login` 修正失效，`run-restore-verdict` 也一併受影響。已改成接受 `(login)` 這個根程序，shell 本身仍然要讀得到參數。

這個問題測試抓不到，以後要注意：

- 單元測試強制走 `ps`（`loadLibprocAddon` 在 Vitest 下回傳 null），而 setuid 的 `ps` 讀得到 `login` 的參數。
- E2E 的 macOS 分頁沒有 `login`，所以 Phase 3、5 也不能只靠 E2E 判斷這類邏輯。
- 要驗證程序表相關的判斷，要用 `--external:node-pty` 打包並放在 `out/` 底下，以 daemon 的 Electron Helper 執行，才會用到真正的讀取器。
- 這段程式跑在 daemon 裡，daemon 會跨 app 重啟存活；版本號相同時不會被視為過期，所以修正要等 daemon 重啟才生效。舊 daemon 在那之前仍會回報 `false`，訊息因此寫成「似乎還有程式在執行」。

Phase 2 中發現的事：

- **Windows 不能靠前景判斷 ssh 結束**：`windows-agent-foreground-process.ts` 只回報 shell 和已知 agent，所以 Windows 上非 ssh 一律視為未知，不顯示橫幅，也就沒有同分頁重新連線。這是讀程式得到的結論，還沒在 Windows 實測。Phase 3、5 要依 §9.2 處理。
- **名稱不足以判斷能不能打字**：執行中的 `bash deploy.sh` 也叫 `bash`，Ctrl+C 會殺掉它。重新連線改看 `inspectProcess` 的 `shellOwnsEveryTtyProcessGroup`，查不到就不送。常用指令和同步輸入要用同一個判斷。
- `pendingStartupByTabId` 在 PTY 建立時就清掉，不是打完指令才清，看不出 shell 還在啟動。所以寬限期拉長到 20 秒，ssh 出現時橫幅自動消失。
- 舊的 session 在 `reconnection-failed` 之後不會自己離開 `sessions`，要在 `ensureSession` 換掉，否則「重新連線」拿到的還是死掉的連線。
- 瀏覽類操作（包含長時間的刪除）也要算進閒置計時，否則會被閒置斷線切斷。

審查後刻意維持的做法：

- **只輪詢畫面上的分頁**，其他分頁切過去才更新。9 個窗格的並列（Phase 4）要重新看這點。
- **ssh 秒退的連線，橫幅最多等 20 秒**：連線被拒絕時 ssh 可能在兩次輪詢之間就結束，只能等寬限期。
- **登入 shell 超過 20 秒才打完指令時，橫幅會短暫誤報**，ssh 一出現就消失；這時按重新連線，可能多打一次 ssh 指令。
- **沒看過 ssh、前景又是不認識的程式就顯示未知**：可能是 `autossh`、`kitten ssh` 這類包裝程式，寧可不提示也不誤報。
- **main 收到中斷連線時，傳輸還在跑就直接忽略**：按鈕本身會提示，main 只是防另一個視窗不知道有傳輸。
